# The web app loads network-first and retries a failed module at a new address

With no bundler (ADR 0009), what reaches the browser is the files themselves, and three choices about how they load look odd without the reason.

The service worker (`/sw.js`) fetches the app's own files from the network and keeps a copy, rather than serving the copy first. Serving the copy first would show every update one load late, and could pair a new page with an old script. On a slow connection it uses the copy after 1 s, and the late reply still replaces it. A pairing can still happen file by file, so a newer `app.js` makes the rail's element itself when a kept older `/app/` has none (`railRoot`), rather than drawing into nothing. Vendored files carry their version in their folder's name, so they come from the copy first; the `@` there is written `%40`, since Cloudflare's static assets redirect the `@` form and that cost a round trip per file.

A browser keeps a module that failed to load as failed for the life of the page, so `import()` of the same address fails again without asking the network. The lazy tabs (`loadTab` in `app/app.js`) and MapLibre with PMTiles (`app/map.js`) are retried at a new address, `?retry=N`; the service worker keeps them under the address without it. A retry renews only the file named, not what that file imports, so what the Stops and Map tabs both import (`app/board.js`) comes with the page instead, through `app/sign.js`. MapLibre's shared half, which it imports itself, keeps its address: if that file is what failed, only a reload fetches it again. Reloading the page on a failed tab was rejected: it loses what's on screen and needs the connection the import just lacked.

What has to be in place before the first paint loads as a classic script or a render-blocking module that imports nothing, not through `ui.js`. `assets/theme.js` and `assets/sky-phase.js` set `<html data-theme>` and `data-sky` from `<head>`. `assets/i18n.js` writes the `zh.js` script into the parser with `document.write`, so the Chinese is there before any module words what it builds with `t()`; it is same-origin, so no browser holds it back. `assets/stars.js` loads with `blocking="render"` and imports nothing, so holding the paint for it costs one small file fetched with the stylesheets, not the whole of Preact. `assets/errors.js` is a classic script ahead of the modules, so an error while they load is reported too.
