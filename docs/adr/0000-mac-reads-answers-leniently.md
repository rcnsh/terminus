# The Mac reads each answer field by field, on the server's clock

The Mac decodes every answer leniently. Only `label` is required in `/api/me/next`, `kind` in its card, the stop in a Nearby stop and the four names in a destination; every other field is read on its own, and a list drops the elements it can't read (`lenientList`, `lenientInt`, `Lossy` in `Api.swift`). A newer server adds fields and an older one lacks them, and a strict `Codable` read turned one odd field (a walk time sent as 95.5, a phase this version doesn't know) into "Offline" for the whole answer. `AnswerTests.everyGoldenAnswerDecodes` holds the other side: each part a golden sends must come through, so a lenient read can't hide a real change in shape. A phase or quality this version doesn't know is neither a trip under way nor live: the dot is grey and no reminder is scheduled for it. The profile is kept as JSON rather than decoded, so fields this version doesn't know survive a save.

Times in answers are the server's, so the Mac counts them down on the server's clock (`ServerClock`), not its own: a Mac clock a minute out would count every leave-by a minute out. The skew is learned from the HTTP `Date` header of uncached (`no-store`) API responses, since a cached one carries the time it was first sent, and anything under 3 s is taken as `Date`'s one-second steps and the trip there, not a wrong clock. Every clock time is shown in Singapore's zone (`TimeZone.campus`), whatever the Mac is set to, because the server words class times and arrivals in it, and in the account's 12- or 24-hour choice (`Clock`), kept on the Mac so the menu bar has it before the profile loads.

Every reply is also checked against the sign-in it was asked for: `AppModel.session` moves whenever the token changes, and a reply to a request made with the old one is dropped, not shown for the new account. Setup and Settings windows stay open across a sign-in, so `SetupModel` keeps the session it loaded for and refuses edits until the new account's setup has loaded.

We considered strict decoding with a version check, which fails the same way the first time the server moves ahead, and trusting the Mac's clock, which is wrong on exactly the Macs where it matters.
