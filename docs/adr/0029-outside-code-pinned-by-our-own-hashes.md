# Outside code is pinned by hashes kept here, and new releases wait a few days

A registry or a release page checks what it serves against its own record, which is no help when the release itself was swapped or republished upstream. So everything terminus ships, builds with or hands a key to is checked against a hash committed in this repo, which only a reviewed commit changes, and a new upstream version waits before it's taken.

- **Vendored web code** (`scripts/vendor/vendor-*.sh`, with `vendor-lib.sh`). Each npm tarball is checked against an integrity pinned in its script before it's unpacked. Another version's integrity is passed in by the person updating, looked up with `npm view <pkg>@<version> dist.integrity`, never read from the registry that serves the tarball. A licence must be there (pmtiles' isn't in its package, so it's taken from the PMTiles repository at the commit npm says the version was built from, checked by SHA-256), and every file written is recorded in `vendor/SHA256SUMS`, which `vendor.test.js` holds the folder to. `/vendor/` is kept by browsers for a year, so a folder's files never change under its name: a new htm with the same Preact is refused. Preact's folder has no `@` (Cloudflare's static assets redirect `@` to `%40`, a round trip per import); the map's and Mediabunny's are linked as `%40`. Mediabunny (MPL-2.0) is never edited beyond dropping its source-map line.
- **The Mac's MapLibre** (`scripts/vendor/vendor-maplibre-mac.sh`) is built from source, as no macOS build is published: from the tag's peeled commit, so a moved tag stops the build, and only from a clean checkout, submodules included. The build isn't reproducible (Bazel, Xcode and the toolchain all leave their mark), so `MapLibre.xcframework.zip.sha256`, which CI checks, records what was committed rather than proving its source; the tag and commit in the commit message do that. CI also fails a framework that links anything outside macOS: MapLibre's Bazel files link libpng, libjpeg and libwebp, which the linker found in Homebrew, and the app then loaded only on a Mac with Homebrew, so the build passes `-dead_strip_dylibs`.
- **The release** (`scripts/release/release-lib.sh`) deletes `node_modules` and `apps/macos/.build` and installs from the lockfiles (`--frozen-lockfile`, `--force-resolved-versions`), since both are ignored by git and anything left in them would run beside the release's keys. Sparkle's `sign_update` is signed ad hoc, so codesign can't say who built it: it gets the Sparkle key only when its SHA-256 matches `SIGN_UPDATE_SHA256` and `Package.resolved` pins `SPARKLE_VERSION`, checked again just before it's used, since the builds since ran code too.
- **The street map** (`scripts/map-tiles.lock`), **Android's dependencies** (`gradle/verification-metadata.xml`, written from an empty Gradle home, as a cold CI runner fetches files a warm cache leaves out) and **SwiftPM** (`Package.resolved`, built with `--force-resolved-versions` so a moved tag fails) are held the same way.

Every Dependabot ecosystem has a five-day cooldown, and pnpm installs nothing published less than three days ago (`minimumReleaseAge: 4320`, in minutes): a compromised release is usually caught and pulled within that. The cooldown is also all that stands between a bad Gradle plugin and the `android deps` workflow, which runs the new versions' code before any hash is checked.

A CDN for the web code, a prebuilt MapLibre from Homebrew or a release built from whatever is installed would each be simpler. They were rejected because each trusts a copy nobody here reviewed.
